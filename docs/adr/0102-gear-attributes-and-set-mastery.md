# ADR-0102：装备属性重标定与套装完整特效

- 状态：Accepted（2026-11-08）
- 影响范围：`bongocat-pomodoro` 的 `cultivation::items` / `state_actions`，三端装备面板

## 背景

旧的装备表有两个问题：同一槽位的次属性写死（武器永远是力量+法力），同槽位同阶同品质只有 ±6% 的成色差；套装每多一件支付完全相同的加成，凑齐 4 件只是把同一份数值加第三次，没有"完成"这个时刻。玩家想要的差异化和收集动机都不在这张表里。

## 决策

1. **玩家掉落表**：裤子主属性改法力；每件装备（所有品质）都有主属性 + 一条从其余 3 种属性中等概率抽出的次属性；成色抽一个 100‰～300‰ 的幅度并随机取上下方向，单件落在名义值的 0.70～0.90 或 1.10～1.30 倍。
2. **预算口径不变**：`budget = points × (p × w(primary) + (1-p) × w(nominal_secondary))`。名义次属性只用于定价，实际次属性只用于把功率换成点数。因此随机次属性改变的是面板读数，不是这件装备的战力；浮动本身期望为 0，长线不膨胀。
3. **对手表解耦**：`roll_equipment_solo` 走 `guardian_split()`、旧 ±6% 成色、旧品质词条数与 `MASTERWORK_CEILING_PERMILLE = 1060`，全部 `held_constant`。玩家侧的调参不得重穿守卫的一身装备，否则破境与锁妖塔分带会被悄悄改动。
4. **套装凸阶梯**：`SET_PIECE_PERMILLE = [0, 0, 200, 550, 1000]`，完整值 `3 × tier × lines()`（等于旧 4 件线性总量）。2/3/4 件支付 20/55/100%，边际 20→35→45 递增。4 件额外唤醒 `mastery_effect()`：曜日/幽冥→碎甲，寒渊/磐岳→蛊蚀，惊雷/疾风→雷亟，沧澜/玄铁→寒霜，深度取 `Rarity::Divine`。
5. **特效通道**：`active_effects()` = 最深的神装效果 + 完整套特效；四种效果作用于对手不同数值，因此可并存；同名时只保留更深的一次，不叠同一口咬。战斗在 `duel_with_effects` 构建时读取，面板与实战是同一个数。
6. **持久化**：`EquipmentRecord` 不增字段，改的是掉落时的计算，旧存档数值原样保留。`GearSetView` 新增 `effect`（view，不落盘），旧前端忽略即可。

## 验证（跑之前写死的信号）

| 信号 | 判据 | 结果 |
|---|---|---|
| pass | `cargo test -p bongocat-pomodoro --lib` 全绿；新增覆盖次属性 3 种、裤子主属性、浮动带与均值、套装阶梯与特效、双效果通道 | 411 passed / 0 failed |
| fail | 任一上述断言失败，或 `just check` 的 fmt/clippy 失败 | 未出现 |
| confounded | 同时改动对手表与玩家表，导致分带测试无归因 | 已用 `guardian_split` 排除；证红探针确认守卫未被重穿（bare 胜率 26/31/37/33 不变） |
| stop | 需要靠调大数值、放宽窗户或改玩家属性权重才能让守卫转绿 | 未触发 |

**守卫证红**：把装备加成置零，`gear_is_what_opens_a_realm` 报 `gear made no difference (98 against 98 of 400)`，证明新守卫会报警。

**守卫换级**：±30% 方差 + 400 场胜率封顶使"单次固定掷骰"退化成掷骰门（筑基 6 次独立掷骰得 61/94/157/207/274/310）。两个回归守卫改为测期望：破境守卫平均 24 套装备、塔分带守卫平均 8 套装备，判据的产品含义（"墙变成过半可开的挑战"、三档 3/5/8 成）不变。

**实测收敛**（48 套 × 400 场）：筑基白装 211/400，其余境界 ≥396；（8 套 × 200 场）塔白装档 40～70 窗内、紫装档 62～92 窗内。

## 采纳门槛

| 字段 | 内容 |
|---|---|
| decision | 玩家掉落按新表滚，对手表钉死，套装按凸阶梯 + 4 件特效 |
| evidence_level | L3（可复现的自动化契约 + 多掷骰收敛数据）；无真人长线留存数据，不宣称 L4 |
| primary_bottleneck | 归因所得：胜率对装备加成是有 400 封顶的凹函数，单次固定掷骰的守卫在新方差下失去判别力；不是"数值力度不够" |
| released_variables | 2 个：掉落分布（次属性 + 成色）、套装曲线（阶梯 + 特效） |
| success_criteria | 411 项内核测试全绿；守卫证红成立；旧存档可读；`just check` 通过 |
| rollback_trigger | 真人实测筑基白装破境率 <50%，或锁妖塔白装档跌出 40～70% → 把 `DROP_SWING_MAX_PERMILLE` 从 300 收窄到 200 并复跑两个守卫 |

## 已知风险

玩家会从多次掉落里挑最好的一件，±30% 让极值上沿更高，长线实际战力高于"期望不变"的静态结论；守卫额度钉死后，这会缓慢抬高玩家相对强度。上线后需按 rollback_trigger 观察塔胜率。
