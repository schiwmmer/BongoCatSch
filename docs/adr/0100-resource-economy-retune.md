# ADR-0100: 资源与采集数值重设计（v2.2）

状态：已落地（代码已实现并通过测试，2026-10-31）
修订：v2.1 → v2.2，按三条要求调整——番茄钟沿用 `gather_duration_permille`、仓库 50 级容量 1 万、探索收益上调；落地时探索与黄阶打工定为 **0.6:1**（初稿的 `ENCOUNTER=140` 实测只能到 0.44，且 140 超出 `roll_walk` 编译期断言，改用 112 + 上调 WANDERER/GUARDIAN）
复核（2026-10-31，逐条对照源码 + 整表重算）：修 `collect_scaled` 的**二次截断**（原先把已截断的单轮值再乘时长，满配仙人 12h 只到 310、且半数工坊等级不加产；现改为原始乘积 × 时长 / 10^9 一次整除，回到 321 且逐级有增量）；据此重算表 3/3b/6 与 §8，修正 `单轮` 公式的 /10^9 笔误（应为 /10^6）、表 1 筑基稀有 28→27、落地清单 `ENCOUNTER` 残留的 140→112
不改：境界阶梯（ADR-0094）、战斗数值、试炼与打工的灵石 purse（`WALK_STONES` 以外的 `StonePurse`）

## 1. 背景：现行体系的三处结构性缺陷

现行参数（v1）：`BASE_COMMON_YIELD=10`、`BASE_RARE_YIELD=3`、技能 +5%/级、工坊 +10%/级、仓库 +25%/级、
铁匠铺 0.9^lv、道场 +10%/级，建筑成本 `石=40×rank`，升星材料恒为 `木3 石2（6 星起 +铁2）`。

| # | 问题 | 依据 |
| --- | --- | --- |
| 1 | **煤没有 sink** | `star_up_cost` 与 `building_upgrade_cost` 只花 木/石/铁；全仓没有一处消耗 `Resource::Coal` |
| 2 | **升星材料与星级无关** | 每次恒定 3 木 2 石，1 星与 10 星同价，材料不构成成本曲线 |
| 3 | **建筑无停止点，境界无需求** | 成本线性、加成线性 → 每级性价比递增；采集只随境界放大 3.25 倍，而境界天数 6→744 天 → 后期材料过剩百倍 |

## 2. v2.2 相对 v2.1 的三处调整

| 要求 | 调整 |
| --- | --- |
| 番茄钟仍用 `gather_duration_permille(realm)` | 番茄钟轮数 = 轮/小时(realm) × **`gather_duration_permille(realm)`**（1.00 h → 3.25 h），不再固定 2 h。两个量从此分开命名，不再共用同一个常量 |
| 仓库 50 级、每种 1 万容量、材料加量 | 容量 `400 + 192×lv`（50 级 = 10000），成本 `10 × 1.09^(rank−1)`，累计 **8151 木**（v2.1 是 2322） |
| 提升探索收益 | `WALK_STONES` 2–4 → **3–5**，`ENCOUNTER_PERMILLE` 90 → **112**，`WANDERER_STONES` 20–34 → **48–68**（探索对齐黄阶 0.6:1 的随动项） |

### 2.1 番茄钟的两个时间量必须分开命名

v1 把 `gather_duration_permille(realm)` 一个常量当两个量用：它既是"一次采集 session 的小时数"（喂给 `collect_scaled`），又被 `expedition_yield` 当成"每小时轮数"。数值都是 1000+250×realm，所以看不出来。

v2.2 拆成两条独立的量：

```
轮/小时        rounds_per_hour_permille(realm) = 1000 + 150 × realm   // 1.00 → 2.35，外出用
番茄钟时长      gather_duration_permille(realm) = 1000 + 250 × realm   // 1.00h → 3.25h，番茄钟用
番茄钟轮数      = 轮/小时 × 番茄钟时长 / 1000                          // 1.0 → 7.6 轮
```

番茄钟随境界增长 **7.6 倍**（2.35 × 3.25），而 12 小时外出只涨 2.35 倍——番茄钟在高境界更值得点。这是本次改动的意图，不是副作用。

### 2.2 为什么产量与材料需求必须同比例减半（沿用 v2.1 的结论）

只降产量 → 一件装备要 13 趟（炼气期不可能）；只降需求 → 采集变成碾压按钮。两者同比例降，趟数节奏不变，采集的灵石当量回到打工量级。

## 3. 采集

```
原始乘积 = base × (1000 + 50×技能) × (1000 + 90×工坊)        // base: 常见 4、稀有 2
单轮产量 = 原始乘积 / 10^6                                  // 一次采集的一轮
一次外出 = 原始乘积 × 轮/时_千分比(realm) × 时长(4/8/12) / 10^9
一次番茄钟 = 原始乘积 × 时长_千分比 / 10^9
             其中 时长_千分比 = 轮/时_千分比(realm) × 番茄钟时长_千分比(realm) / 1000
```

每条都是**只做一次整除**（`原始乘积` 先乘完所有系数，最后一次除以 10^6 或 10^9）。

三条实现约束：

1. **只在最后截断一次**。v1 的 `scale_yield` 与 `collect_scaled` 分三段整除，把工坊低级的增量吃成 0（实测工坊 5→6 级产出不变）。
2. **境界只乘轮数**，不乘单轮产量。
3. **三档时长线性**（12h = 3×4h）。

## 4. 升星

```
第 s 星（当前 s，目标 s+1）：
  木 = 2 + 2s        石 = 1 + s
  铁 = 0 if s+1 < 6  else 1 + (s+1-6)
  煤 = 0 if s+1 < 4  else 1 + (s+1-4)
  灵石 = 售价/10 × 铁匠铺折扣
  整份再乘阶系数 = (1000 + 850×(tier-1)) / 1000     （tier1 ×1.0 → tier10 ×8.65）
成功率：900/870/840/810/770/730/680/620/550/460 ‰，失败掉 1 星
```

- **wager 从 v1 的 售价/3 降到 售价/10**：v1 升满一件 = 6.4 倍装备价，灵石是绝对瓶颈；改为 1.25 倍后，材料占 40%、灵石占 60%。
- **末星 46%**（v1 31%）：材料已成双轴成本，不再叠加第二重惩罚。
- **材料随阶放大 8.65 倍**：让"一件满星要几趟"跨境界恒定（表 8）。

## 6. 探索：对齐黄阶打工（0.6:1）

v1/v2 的探索是三者中最低的（12h 只给 9–90 灵石，2–19 当量/h），因为它的价值被放在"掉落"上，而灵石底薪几乎为零。

```
WALK_STONES        2–4 → 3–5          （4h 基准，12h 走按 3000‰ 展宽）
ENCOUNTER_PERMILLE  90  → 112         （4h 基准，12h 走 = 35.8% 遇事）
WANDERER_STONES    20–34 → 48–68      （遇事给得更多：把探索抬到 0.6 的关键）
GUARDIAN_STONES    38–66 → 70–120     （破境守卫：随 WANDERER 上调，保住断言链）
```

**为什么不是 1:1**：初稿按 `ENCOUNTER=140` 对齐黄阶（1.0 倍），但 `roll_walk` 的编译期断言 `(SEED+GEAR+ART+ENCOUNTER)×3.2 ≤ 1000` 把 ENCOUNTER 卡在 **112** 以内——140 无法编译；而在 140 可用窗口内探索只能到 **0.44 倍**。要把探索抬到黄阶，必须把价值从"遇事概率"挪到"遇事给得更多"（`WANDERER` 上调到均值 58）。实测 **ENCOUNTER=112 + WANDERER 48–68** 精确落在 **0.600**。

| 境界 | 探索旧/h | 探索新/h | 打工黄/h | 采集/h |
| --- | --- | --- | --- | --- |
| 炼气 | 2 | **2.4** | 4 | 12 |
| 化神 | 9 | **12.0** | 20 | 32 |
| 仙人 | 19 | **24.0** | 40 | 80 |

断言链仍然成立：`WALK.max(5) < PROVING.min(6) < TRIAL.min(12) < WANDERER.min(48) < GUARDIAN.min(70)`。

**设计后果（随动项，非本意）**：`GUARDIAN`（破境守卫灵石）从 38–66 上调到 70–120，否则 `WANDERER.max(68) < GUARDIAN.min` 链会断。这提高了破境守卫的灵石收益——是断言链的必然结果，不是本轮的目标。若破境经济因此偏离，需在实机回放中单独评估。

三条曲线的关系（大致同向；采集随境界增长快于打工，比值会随境界略降，不是严格恒定）：

- **探索 ≈ 黄阶打工 × 0.6**：两者都是"无门槛、纯时间换灵石"，探索略低是因为它顺带产出掉落（装备/功法/种子），灵石只是底薪——0.6 把"顺带"的价值留给了掉落，不把无门槛活动的灵石抬到与打工平齐。
- **采集 ≈ 黄阶 2–3 倍 / 地阶 0.7–0.8 倍**：材料用途窄、不能变现、受仓库上限约束，单位价值本就该高于灵石（炼气期比值高、仙人偏低，绝对值以 §3 公式为准）。
- **地阶与神阶打工是难度奖励**：属性门槛越高给得越多，不该被无门槛活动追上。

## 8. 自洽校验

| 检查 | 结果 |
| --- | --- |
| 仓库硬阻塞 | 无。tier10 单件 2897 木 < 满级 10000；0 级 400 也装得下一趟 321 |
| 早期可行性 | 炼气 6 天：6 趟 12h = 288 木 + 每天 4 次番茄钟（4 木）= 96 → 约 384；一件到 6 星需 94 → 够 4 件 |
| 一件满星趟数 | 一阶 ≈7.0 趟（336 木 / 48）、十阶 ≈9.0 趟（2897 木 / 321），跨境界大致恒定在 7–9 趟 |
| 升星成本结构 | tier10 一件材料 ≈5563 单位（木2897/石1440/铁432/煤794，≈17 趟采集）+ 灵石 wager（≈12 次黄阶打工），材料约占四成、灵石六成（量级估计，随境界略有浮动） |
| 断言链 | `WALK.max < PROVING.min` 仍成立（5 < 6），探索提升不波及打工 purse |
| 通货紧缩 | 无。材料无兑换出口，不存在材料换灵石的套利 |

**已知局限（不掩盖）**：境界天数从 6 天涨到 744 天，而装备槽固定。化神 40 天采 40 趟、只需 ~20 趟就补齐当境界装备与建筑，**采集的经济寿命到合体（第 6 境）为止**；大乘之后每境界只需 3–5 趟。要延长只能加新 sink（炼器/符箓/材料炼灵石），超出本次范围。

## 10. 采纳门槛

| 字段 | 内容 |
| --- | --- |
| `decision` | 资源/采集/升星/建筑/探索五组数值换成 v2.2；番茄钟时长仍由 `gather_duration_permille` 决定；仓库扩到 50 级、1 万容量 |
| `evidence_level` | L1 — 全部数字由公式与马尔可夫期望复算，含三方收益对标；尚无实机存档回放 |
| `primary_bottleneck` | 煤无 sink、升星材料与星数无关、建筑成本线性（源码确认）；追加：材料需求不随阶缩放（后期材料变废纸）、探索灵石底薪几乎为零 |
| `released_variables` | 3 个：①产量与材料需求的绝对量（同比例减半）②阶系数（1.9 → 8.65）③仓库上限（10 级/5000 → 50 级/10000）。探索两常量作为第三条要求的随动项 |
| `success_criteria` | ①满配仙人 12h 321 ≤ 仓库 0 级 400（采集本身不逼升级）②tier10 单件 2569 ≤ 满级 10000 ③一件满星跨境界 6–10 趟 ④采集当量/h 与地阶打工的比值在 0.5–1.3（实测 0.83–1.2）⑤探索/h 与黄阶打工的比值在 0.5–0.7（实测 0.600）⑥番茄钟 = 1.00–3.25 h 外出量 ⑦工坊产量逐级不减且满级 > 零级（基础产量减半后每级增量是亚整数，逐级严格递增不可达，改为非降 + 总增） |
| `rollback_trigger` | 实机 5 个番茄钟 + 3 趟采集后，若 (a) 炼气期六天内升不起第一件 6 星，或 (b) 采满一趟触发溢出且无出口，或 (c) 单件升星超过 25 次点击，回滚到 v1 常量并重新归因 |
