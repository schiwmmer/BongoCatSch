# ADR-0100: 资源与采集数值重设计（v2.1）

状态：提案（2026-10-31，待批准后落地）
修订：v2 → v2.1，按三条要求调整——仓库 50 级、番茄钟采集 2 小时量、三方小时收益对齐
不改：境界阶梯（ADR-0094）、战斗数值、灵石 faucet（走/试炼/打工/日赠）

## 1. 背景：现行体系的三处结构性缺陷

现行参数（v1）：`BASE_COMMON_YIELD=10`、`BASE_RARE_YIELD=3`、技能 +5%/级、工坊 +10%/级、仓库 +25%/级、
铁匠铺 0.9^lv、道场 +10%/级，建筑成本 `石=40×rank`，升星材料恒为 `木3 石2（6 星起 +铁2）`。

实测三处问题：

| # | 问题 | 依据 |
| --- | --- | --- |
| 1 | **煤没有 sink** | `star_up_cost` 与 `building_upgrade_cost` 只花 木/石/铁；全仓没有任何一处消耗 `Resource::Coal`。煤是纯 faucet，采煤永远是无用功 |
| 2 | **升星材料与星级无关** | 每次尝试恒 3 木 2 石，1 星与 10 星同价。材料不构成成本曲线，全部压力落在灵石与 31% 的末星成功率上 |
| 3 | **建筑无停止点，境界无需求** | 成本线性、加成线性 → 每级性价比递增，玩家只会按固定顺序全部升满。同时采集只随境界放大 3.25 倍，而境界天数从 6 天涨到 744 天 → 后期材料过剩百倍 |

## 2. v2.1 相对 v2 的三处调整

| 要求 | 调整 | 影响面 |
| --- | --- | --- |
| 仓库要 50 级 | 容量 400 → 5000（每级 +230‰），成本 8×1.06^(rank−1)，累计 2322 木 | 新增 `MAX_WAREHOUSE_LEVEL`，其余建筑仍 10 级 |
| 番茄钟采集 ≈ 2 小时量、随境界提升 | 采集番茄钟的时长固定 2 小时，产量 = 2h × 该境界轮/小时 | `collect_session` 不再用 `gather_duration_permille` |
| 采集小时收益与探索/打工对齐 | 产量与材料需求**同比例减半**（常见 10→4、稀有 3→2、升星 6+4s→2+2s、建筑 10→5），阶系数放大到 ×8.65 | 采集当量/h 从 157 降到 80（黄阶打工 40、地阶 96） |

**为什么产量和需求一起减半**：只减产量会让"一件装备要 13 趟"（炼气期根本不可能）；只减需求会让采集变成碾压按钮。两者同比例降，趟数节奏不变，但采集的灵石当量回到打工量级。

**为什么阶系数从 ×1.9 放大到 ×8.65**：v2 里 tier10 一件只要 1.8 趟、tier1 要 6.2 趟——越后期材料越不值钱，采集成废玩法。放大后任何境界一件满星都是 6–10 趟，材料需求跟着境界走。

## 3. 采集

```
轮/小时      = 1000 + 150 × realm        (‰，炼气 1.00 → 仙人 2.35)
单轮常见产量 = 4 × (1000 + 50×技能) × (1000 + 90×工坊) / 10^9
单轮稀有产量 = 2 × 同上
一趟产出     = 单轮 × 轮/小时 × 时长
番茄钟产出   = 单轮 × 轮/小时 × 2
```

三条实现约束：

1. **只在最后截断一次**。v1 的 `scale_yield` 与 `collect_scaled` 分三段整除，把工坊低级的增量吃成 0（实测工坊 5→6 级产出不变）。
2. **境界只乘轮数**，不乘单轮产量。三处相乘会让后期平方膨胀。
3. **三档时长线性**（12h = 3×4h）。采集是挂机产出，非线性只会让最短档变成唯一最优按钮（同 `jobs.rs` 对工资的判断）。

## 4. 升星

```
第 s 星（当前 s，目标 s+1）：
  木 = 2 + 2s        石 = 1 + s
  铁 = 0 if s+1 < 6  else 1 + (s+1-6)
  煤 = 0 if s+1 < 4  else 1 + (s+1-4)
  灵石 = 售价/10 × 铁匠铺折扣
  整份再乘阶系数 = (1000 + 850×(tier-1)) / 1000     （tier1 ×1.0 → tier10 ×8.65）
成功率：900/870/840/810/770/730/680/620/550/460 ‰，失败掉 1 星
```

- **wager 从 v1 的 售价/3 降到 售价/10**。v1 升满一件 = 6.4 倍装备价，灵石是绝对瓶颈；改为 1.25 倍后，材料占 40%、灵石占 60%。
- **末星 46%**（v1 31%）：材料已成双轴成本，不再叠加第二重惩罚。
- **材料随阶放大 8.65 倍，上限由仓库卡死**：tier10 一件需 2569 木，必须小于仓库满级 5000。

## 6. 三方小时收益对标（第三条要求的直接回答）

同一境界、同样 12 小时、采集用该境界的典型配置（技能/工坊按进度估）、材料按 2 灵石/单位折算
（该汇率由"十级建筑里材料 500 单位与 2200 灵石并列"反推）。

**结论：采集稳定落在"黄阶打工"与"地阶打工"之间**（黄阶的 1.2–3.0 倍、地阶的 0.8–1.2 倍），跨十个境界比例基本不变——因为采集与打工都是线性随境界缩放。

- 略高于黄阶打工是刻意的：材料只能进升星与建筑两条 sink、不能变现、还受仓库上限约束，用途窄的货币单位价值本就该低。
- 远低于神阶打工是刻意的：那是高战力玩家的难度奖励，不该被无门槛的采集追上。
- **探索明显偏低（2–19/h）**：它的价值在种子/装备/功法掉落，不在灵石，这里只折算灵石部分，实际高于表值。若要让三者真正等值，应同步上调 `WALK_STONES` 或遭遇率——不在本次范围，列为已知问题。

## 7. 自洽校验

| 检查 | 结果 |
| --- | --- |
| 仓库硬阻塞 | 无。tier10 单件 2569 木 < 满级 5000；仓库 0 级（400）只够装单趟产量的 3 倍，早期不逼升级 |
| 溢出边界 | 满配 12h = 321，仓库 1 级（492）就装得下 → 采集本身不逼仓库；**逼仓库的是囤积两件以上装备的料** |
| 时间占比 | tier10 一件满星 = 8 趟采集 + 12 次打工（黄阶），材料 40% / 灵石 60% |
| 早期可行性 | 炼气 6 天、6 趟 12h = 288 木，加番茄钟采集（8 木 × 4/天 = 192）≈ 480；一件到 6 星需 84 → 够 5 件 |
| 通货紧缩 | 无。材料无兑换出口，不存在材料换灵石的套利 |
| 通胀 | 存在但有上限：建筑是买断制，材料只在升星上重复消耗 |

**已知局限（不掩盖）**：境界天数从 6 天涨到 744 天，而装备槽固定。化神 40 天采 40 趟、只需 ~20 趟就能补齐当境界装备与建筑，**采集的经济寿命到合体（第 6 境）为止**；大乘之后每境界只需 3–5 趟。要延长只能加新 sink（炼器/符箓/材料炼灵石），超出本次范围。

## 9. 采纳门槛

| 字段 | 内容 |
| --- | --- |
| `decision` | 资源/采集/升星/建筑四组数值换成 v2.1，并把仓库扩到 50 级、番茄钟采集定为 2 小时量 |
| `evidence_level` | L1 — 全部数字由公式与马尔可夫期望复算，含三方收益对标；尚无实机存档回放 |
| `primary_bottleneck` | 煤无 sink、升星材料与星数无关、建筑成本线性（三者从源码确认）；追加一个：材料需求不随阶缩放，使后期采集成废玩法 |
| `released_variables` | 3 个（本次比上次多一个，因为要求本身变了）：①产量与需求的绝对量（同比例减半）②阶系数（1.9 → 8.65）③仓库等级上限（10 → 50）。其余作为随动参数一次改完 |
| `success_criteria` | ①满配仙人 12h 321 ≤ 仓库 1 级 492（采集本身不逼升级）②tier10 单件 2569 ≤ 满级 5000 ③一件满星跨境界 6–10 趟 ④采集当量/h 与地阶打工的比值在 0.5–1.3 之间（实测 0.83–1.2）⑤番茄钟 = 12h 的 1/6 ⑥工坊每级增量 > 0 |
| `rollback_trigger` | 实机 5 个番茄钟 + 3 趟采集后，若 (a) 炼气期六天内升不起第一件 6 星，或 (b) 采满一趟触发溢出且无出口，或 (c) 单件升星超过 25 次点击，回滚到 v1 常量并重新归因 |
