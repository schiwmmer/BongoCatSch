# ADR-0100: 资源与采集数值重设计（v2）

状态：提案（2026-10-31，待批准后落地）
范围：`cultivation/resources.rs` 的全部常量与公式、`shop::star_up_cost`、`shop::equipment_price` 的解读口径
不改：境界阶梯（ADR-0094）、战斗数值、灵石 faucet（走/试炼/打工/日赠）

## 1. 背景：现行体系的三处结构性缺陷

现行参数（v1）：`BASE_COMMON_YIELD=10`、`BASE_RARE_YIELD=3`、技能 +5%/级、工坊 +10%/级、仓库 +25%/级、
铁匠铺 0.9^lv、道场 +10%/级，建筑成本 `石=40×rank`，升星材料恒为 `木3 石2（6 星起 +铁2）`。

实测三处问题：

| # | 问题 | 依据 |
| --- | --- | --- |
| 1 | **煤没有 sink** | `star_up_cost` 与 `building_upgrade_cost` 只花 木/石/铁；全仓没有任何一处消耗 `Resource::Coal`。煤是纯 faucet，采集它永远是无用功 |
| 2 | **升星材料与星级无关** | 每次尝试恒 3 木 2 石，1 星与 10 星同价。材料不构成"高星是决定"的成本曲线，全部压力落在灵石与 31% 的末星成功率上 |
| 3 | **建筑无停止点，境界无需求** | 成本线性（40×rank）、加成线性（+100%/+250%/-65%/+100%）→ 每级性价比递增，玩家只会按固定顺序全部升满。同时境界只把采集时长放大 3.25 倍，而境界天数从炼气 6 天涨到仙人 744 天（ADR-0094）→ 后期材料过剩百倍，采集成死玩法 |

第 3 条不是调数值能修的，它要求**成本随 rank 超线性**（制造停止点）且**稀有用量随 tier 放大**（贴合后期）。

## 2. 决策总览

四资源改为**四个专属下游**，让"去哪儿采"成为决策而不是随机：

| 资源 | 采集点 | 专属下游 |
| --- | --- | --- |
| 木 | 森林 | 工坊、仓库、道场（通用主料） |
| 石 | 山 | 铁匠铺主料、其余副料 |
| 铁 | 山（采石 3 级）、矿洞 | 铁匠铺 6 级起、升星 6 星起 |
| 煤 | 森林（伐木 5 级）、矿洞 | 工坊 3 级起、升星 4 星起 |

- 森林 → 工坊；山 → 铁匠铺；矿洞 → 高星升星。三个采集点各有明确去处，煤不再是废料。
- 仓库与道场吃通用木石，早期与另外两者竞争同一批料。

## 3. 采集：每境界的单位时间产量

```
轮/小时      = 1000 + 150 × realm        (‰，炼气 1.00 → 仙人 2.35)
单轮常见产量 = 10 × (1000 + 50×技能) × (1000 + 90×工坊) / 10^9
单轮稀有产量 = 3  × 同上
一趟产出     = 单轮 × 轮/小时 × 时长
```

三条实现约束（缺一条数值就会失真）：

1. **只在最后截断一次**。先算 `单轮 × 轮数` 再乘乘数、分两次整除，会让工坊低级的增量被吃掉（实测 v1 的 `scale_yield` 两级截断使工坊 5→6 级增量显示为 0）。
2. **境界只乘轮数**，不再乘单轮产量。境界 × 技能 × 工坊三处相乘会让后期产量平方膨胀（v1 满配为 9.75 倍基数，v2 压到 5.6 倍）。
3. **三档时长线性**（12h = 3×4h）。不做非线性奖励：采集是挂机产出，操作成本近零，非线性的唯一效果是让最短档变成唯一最优按钮（同 `jobs.rs` 对工资的判断）。

## 4. 升星：材料随星数与阶数双轴增长

```
第 s 星（当前 s，目标 s+1）：
  木 = 6 + 4s          石 = 2 + 2s
  铁 = 0 if s+1 < 6    else 2 × (1 + (s+1-6))
  煤 = 0 if s+1 < 4    else 2 × (1 + (s+1-4))
  灵石 = 售价/5 × 铁匠铺折扣          （v1 是 售价/3）
  整份再乘阶系数 = (1000 + 111×(tier-1)) / 1000     （tier10 = ×2.0）
成功率：900/870/840/810/770/730/680/620/550/460 ‰，失败仍掉 1 星（下限 1 星）
```

关键取舍：

- **末星成功率抬到 46%**（v1 31%）。材料已成双轴成本，不再叠加第二重惩罚；同时把末三星期望尝试从 13.7 次压到 9.4 次。
- **灵石 wager 从 售价/3 降到 售价/5**。材料总需求涨了约 2 倍，灵石轴必须同向减负，否则单件升满要 18 次神阶打工。
- **失败掉星保留**。这是"深星是决定"的唯一来源，去掉后高星就只是点击次数。
- **材料随阶乘 1.0→2.0，上限由仓库卡死**：tier10 一件需 1,284 木，必须小于满级仓库 1,400。系数再高会让"永远攒不够一件"，变成硬阻塞。

## 5. 建筑：线性加成 + 超线性成本 = 自选停止点

## 6. 自洽校验

| 检查 | 结果 |
| --- | --- |
| 早期（炼气 6 天，6 趟 4h） | 供给 240 木；1 件到 6 星需 188 → 够。灵石 22/次 × 6 次 ≈ 130，而 12h 打工只 48 → **早期瓶颈是灵石不是材料**，符合"材料后期才痛"的意图 |
| 仓库硬阻塞 | 无。升星即时扣料，攒不满可分批；tier10 单件 1284 < 满仓 1400 |
| 溢出边界 | 满配仙人 12h = 803，仓库 <4 级必溢出 → 后期升仓库有硬需求，不是可选项 |
| 灵石轴 | tier10 天阶升满 11,489 灵石 ≈ 4–24 次神阶打工（取决于 job 阶）；材料 2 趟 + 灵石 10 次打工 → **高 tier 升星的瓶颈在灵石**，符合"材料给中低阶、灵石给高阶"的分层 |
| 通货紧缩 | 无。材料无兑换出口，只有升星与建筑两个 sink；不存在材料变灵石的套利路径 |
| 通胀 | 存在，见下 |

**已知局限（不掩盖）**：境界天数从 6 天涨到 744 天，而装备槽固定，所以**采集的经济寿命到合体（第 6 境）为止**——合体期一境界供给约 6 万木，需求（2 件 tier7 到 10 星 + 建筑）约 5,000 木。大乘之后每境界只需 3–5 趟补齐装备，采集转为低频补给。要延长寿命只能加新 sink（如材料炼器/符箓），超出本次范围，留作后续 ADR。

## 8. 采纳门槛

| 字段 | 内容 |
| --- | --- |
| `decision` | 资源/采集/升星/建筑四组数值整体换成 v2 参数集 |
| `evidence_level` | L1 — 全部数字由 `/tmp/resource_v2_final.py` 按公式复算、含马尔可夫期望尝试；尚无实机存档回放 |
| `primary_bottleneck` | 煤无 sink（结构性浪费）+ 升星材料与星数无关（无成本曲线）+ 建筑成本线性（无停止点）。三者均从源码确认，不是猜测 |
| `released_variables` | 2 个：①采集境界斜率（250→150‰）②成本形状（线性→超线性）。其余（见上表）作为随动参数一次改完 |
| `success_criteria` | ①满配仙人 12h 产出 ≤ 仓库满级上限（803 ≤ 1400）②tier10 单件升满材料 ≤ 满仓（1284 ≤ 1400）③工坊每级增量 > 0（无零收益级）④早期六趟 4h 的材料够 1 件到 6 星（240 ≥ 188）⑤全部资源在 sink 侧至少被读一次 |
| `rollback_trigger` | 实机 5 个番茄钟 + 3 趟采集后，若 (a) 炼气期材料不足以完成第一件 6 星，或 (b) 采满一趟触发溢出而无任何可花出口，或 (c) 单件升星耗时超过 20 次点击，则回滚到 v1 常量并重新归因 |
