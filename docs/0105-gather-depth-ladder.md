# 采集深度单线化：去掉「凡 / 灵 / 神 / 混沌」这层命名

状态：已采纳并落地（2026-11-19）
范围：`crates/bongocat-pomodoro/src/cultivation/` 的采集深度推导 + App / web / 小程序三端采集卡 + i18n
上游：接管 `docs/0104` §4.2 的「采集点（等级门重排）」表，不改其中的倍率与门等级

---

## 1. 问题

`docs/0104` §4.2 给了同一件事两套说法。数值上它只是三件事：**产出倍率 ×1.0 / ×1.5 / ×2.0 / ×3.0**、**准入等级 1 / 20 / 50 / 80**、**同一个采集点的四个名字**。呈现上它被写成了第二套稀有度体系——凡木林 / 灵木林 / 神木林 / 混沌神木，凡石山 / 铁矿山 / 寒铁窟 / 星辰矿脉。

这套命名撞了三处既有阶梯：

| 阶梯 | 档数 | 词 |
|---|---|---|
| 境界 | 10 | 炼气 … 仙人 |
| 采集深度 | 4 | 凡 / 灵 / 神 / 混沌 |
| 物品品阶 | 5 | 黄 / 玄 / 地 / 天 / 神 |

「神」在两套阶梯里都是顶级，但两套阶梯的顶级并不互相对应；玩家读到「神木林」时无法判断它比「天阶」高还是低。玩家反馈「感觉太复杂了」，指的就是这层：**四个词要背，而它们并不承载第四个独立机制**。

更关键的是，这四档**不是选择，是解锁**。深层没有任何代价（不耗额外体力、不降经验、不掉旧资源），严格更优，所以玩家永远点最深那一层。用一个四词体系去讲三次升级里程碑，复杂度全白付：它没有制造决策，只制造了记忆负担。

---

## 2. 决策

**一条单线，深度由采集等级推导，玩家不选。**

1. 深度仍分四层（机制不变：倍率 ×1.0 / ×1.5 / ×2.0 / ×3.0）。
2. 深度不再是命令参数，也不再是页面状态：`GatherTier::for_level(level)` 是唯一入口，返回这只手**够得着的最深一层**。
3. 界面不再出现「凡 / 灵 / 神 / 混沌」四个词。标签改成数字 + 倍率：`Ⅰ · ×1.0` / `Ⅱ · ×1.5` / `Ⅲ · ×2.0` / `Ⅳ · ×3.0`。
4. 地名保留，但只作为**同一个采集点越走越深的说法**，不是玩家要选的四个地方：森林那条线是凡木林 → 灵木林 → 神木林 → 混沌神木，山那条线是凡石山 → 铁矿山 → 寒铁窟 → 星辰矿脉。它们只在任务行、任务卡与采集通知里跟着当前深度出现。
5. 升到 20 级，林子自己变成灵木林；升到 50 / 80 级同理。没有选择动作，也没有「采集等级不足」的拒绝理由——够不着更深的一层时，玩家本来就已经站在够得着的那一层上。

### 2.1 为什么保留四层而不是压成一层

四层是数值需要的（`docs/0104` §4.2 的 ×1.0/×1.5/×2.0/×3.0 是采集的主增长轴之一），删掉会动经济。这次删的是**表达层**：同一组倍率用一颗数字讲，而不是第二套稀有度词。

### 2.2 为什么保留 `ActiveTask.tier`

`ActiveTask.tier` 仍在存档里，也仍在快照里给三端读，但**不再是输入的副本**：每个 tick 结算前重算一次当前深度，结算后再把它写回任务。这样

- 旧存档里存着一个已经过时的 tier，读进来不会报错（serde 默认 + 每 tick 重写）；
- 同一 tick 内刚跨过 20 级门槛，快照上立刻是新深度，不用等下一个任务；
- 三端不必各自推一遍等级 → 深度的映射，只读快照。

### 2.3 删掉的东西

- `PomodoroCommand::CultStartTask` 的 `tier` 字段（wire 上多余、且可被伪造）。
- `Refusal::TierLocked` 及其 i18n key：门禁没有了，就没有「等级不足」这条拒绝。`last_refusal` 属于 `Cultivation` 而非序列化文档，删变体对旧存档安全。
- App 的 chips 选择器、web 的 `cult-tier` 动作与 `app.cultTier`、小程序的 `task-tier` 与 `taskTier`。
- 内核 `GatherTier::depth()`（零调用的公开方法，AGENTS §6）。

---

## 3. 后果

- **一次性学完**：玩家只需知道「等级越高，同一个地方越深，产出越多」，标签本身就是倍率。
- **三端只剩一处数学**：深度来自 `for_level`，页面不再有 `TASK_TIERS` / `TIER_CHOICES` 之类的第二份表；web 与小程序的 `gatherDepth` 只用来画「我现在在哪一层」，与内核同表（1 / 20 / 50 / 80），结算永远在内核。
- **不新增拒绝路径**：原来「点了深层被拒一次」的体验消失，`last_refusal` 少一个变体。
- **地名第一次真正出现在界面上**：改之前 `cultivation.gather.*` 这 8 个 key 在 catalog 里根本不存在，`site_key` 只有测试引用；现在三端都显示当前地名。
- **代价**：玩家失去了「四个世界」的叙事感，采集点看起来更像同一处的四个深度。这是有意为之——叙事应挂在境界与品阶上，那里本来就有十档与五档。

---

## 4. 兼容

- 旧存档：`ActiveTask` 里的 `tier` 照旧解析（`#[serde(default)]`），第一个 tick 就被重写成按手推导的深度；不迁移、不回滚。
- `schema_version` 仍必须是 1，非 1 明确拒绝（不变）。
- 旧 web/小程序客户端发带 `tier` 的命令：未知字段被忽略，任务照常开始——比原来更宽松，且不会因此错层。
