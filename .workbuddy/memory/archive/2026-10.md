## 根因/修复

### 审计结论自我纠错：`grep` BRE 假阴性差点删掉在用的依赖
- **症状**：10-18 审计报告「两个真实未使用依赖」中的 `uuid`（bongocat-model-store）与 `sys-locale`（bongocat-platform），执行删除前用全仓 ripgrep 交叉验证，发现**都在用**：
  - `uuid::Uuid::new_v4()` → `bongocat-model-store/src/store/mod.rs:245`
  - `sys_locale::get_locale()` → `bongocat-platform/src/macos.rs:51`、`windows.rs:89`
- **根因**：扫描脚本用 `grep -rn "\buuid\b" "$d/src"`。BSD grep 的 BRE **不支持 `\b` 词边界**，模式被当成字面 `buuidb`，0 命中 → 假阴性。同一会话内 `grep "a\|b"`（BRE 不认 `\|`）也连踩 3 次。
- **Correction（硬性，本轮第三次踩同一类坑）**：
  1. 本机 `grep` 是 BSD 版，**BRE 下 `\b`、`\|`、`+`、`?` 全部不生效**。多模式必须 `grep -E`，词边界改用 `grep -w` 或 ripgrep。
  2. **「0 引用」类结论必须用第二种工具交叉验证**：rust 代码里确认 crate 使用，用 ripgrep（Grep 工具）而非 bash grep。删依赖/删 import 前的 grep 一律走 Grep 工具。
  3. 本次两个依赖已声明保留，未做任何删除。

- **番茄钟窗口「创建」无效**：`PomodoroView::submit_task_editor` 原写 `let Some(target) = self.editor.take() else { return }`。但该窗口的「新建任务」表单常态就是 `editor == None`（`editor` 只在编辑/复制时才被 set），于是名字合法、按钮可点、命令永不发布。改 `unwrap_or(PomodoroEditorTarget::New)`。设置页那条同名的 `submit_pomodoro_task_editor` 不受影响（表单只在 `pomodoro_editor.is_some()` 时渲染）。

### 拆分踩坑（复用价值）
- Rust visibility 是相对路径：子模块 `pub(super)` 只到直接父级；要经父级 `pub(super) use` 再导出给祖父级，子模块项必须 `pub(in crate::window)`。
- 父级 import 被子模块 glob 使用**不算**使用——根模块只被子树用的 import 会触发 unused_imports，需在各子模块显式 import。
- 只被 test 构建消费的再导出要挂 `#[cfg(test)]`，否则 lib 构建报 unused import。
- 拆分脚本两次被断言拦下（块间空行覆盖缝隙、struct+impl 同名判重）——fail-closed 有效，原文件零损坏。
